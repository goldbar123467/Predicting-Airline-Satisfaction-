# Six bounded continuation hypotheses

Design review, October 4, 2026. This note uses saved development reports and a bounded refresh of primary papers and official implementation documentation. No predictions were rescored, no audit labels were read, and no model was fitted for this review. The new user authorization covers six sequential experiments and qualifying verified releases; historical no-launch language does not supersede that authorization. Root owns compute, registration and release decisions.

## Evidence and common comparison

The completed dropout experiment's once-only evaluation is `cloud/fixed_epoch_dropout_v1_retry1/assessment_workspace/artifacts/fixed_epoch_dropout_v1/evaluation.json`, SHA-256 `91aede41316207b6662848efaf73f97f40c9a96b8f078c18b7faaab7e52c3d27`. Holding dropout at 0.05 after epoch 4 improved the epoch-16 endpoint by 0.000925676 pooled AUC over its matched scheduled-dropout control, but remained 0.005077037 below the shared epoch-4 endpoint. Its fixed 10% mixture was 0.000047434 below the incumbent. The saved inner curves show improving in-sample probe loss and worsening held-out loss/AUC. This supports continuation overfitting and a partial benefit from this specific dropout intervention. It does not identify the remaining cause.

Every new experiment uses the same H=16 trajectory through completed epoch 4. Both control and treatment then hold the base dropout probability at 0.05. This is a change from the previous experiment's control, whose dropout continued to decline. Both new trajectories run literally to epoch 16, with no best-checkpoint restoration or selected stopping epoch. The new control keeps the original LR, WD, loss and trainable parameter set after epoch 4. Treatments change exactly the policy named below. Each pair recreates and verifies its own prefix; inference-only old checkpoints cannot supply Adam/RNG state for resumption.

Logical endpoints remain A=control16, B=shared treatment-prefix4, C=treatment16. For EMA, C is explicitly the averaged inference endpoint, not the raw live epoch-16 parameters. All six quality evaluations use the same original incumbent and the fixed candidate share 0.10. Release comparison against previously qualifying releases is an additional operational gate, not a moving assessment anchor.

## Ranked policies and exact values

This is a ranked collection of hypotheses, not six equally promising methods or a claim that these values are optimal. The first route directly addresses the long high-LR continuation. The two freezing routes share a family but test different representational boundaries. Their narrow implementation cost is preferable here to adding a second teacher forward and a new distillation objective.

| Order / canonical ID | Single intervention after the verified prefix | Question and limits |
|---|---|---|
| 1 `linear_lr` | For every registered LR schedule scope, replace its multiplier after epoch 4 by `m_scope(4) * max(0, (16-t)/12)`, using the existing pre-update fractional epoch clock `t`; preserve base LR and parameter factors. Mathematical endpoint at t=16 is zero; the last actual update has t<16 and a small positive LR. | Does earlier cooling improve continuation at the same duration? Because decoupled shrink includes the applied LR, this also changes the effective WD dose. It is a continuation-policy contrast, not LR isolated from all regularization. |
| 2 `decay_correction` | After epoch 4, apply the scheduled per-group LR/WD factors once in manual decoupled decay, rather than twice. Preserve nominal WD 0.015, schedules, gradient update LR, Adam state and first four epochs. | Tests the local implementation defect as a continuation intervention. For factors a,b, decay changes from `1-eta*lambda*(a*b)^2` to `1-eta*lambda*a*b`. It is heterogeneous stronger shrink for active groups with a*b<1, not a uniform WD increase or an automatic upstream upgrade. |
| 3 `ema` | Initialize a separate shadow from the epoch-4 live parameters. After every optimizer update use `shadow = beta*shadow + (1-beta)*live`, with `beta=2**(-1/updates_per_epoch)`, a one-epoch half-life. Export the shadow at epoch 16; do not feed it into training. | Does averaging local updates improve the inference endpoint? One half-life, one start and one final endpoint only. After 12 half-lives the direct initial-shadow coefficient is 1/4096, so this is not an attempt to reproduce the good epoch-4 checkpoint. An eight-member ensemble already reduces some variance. |
| 4 `label_smoothing` | Change training targets after epoch 4 to `(1-.05)*one_hot(y)+.05/2`: binary target probabilities .025 and .975. Keep unsmoothed evaluation losses and AUC. | Tests a bounded confidence regularizer. Direct RealMLP evidence is unfavorable for AUROC, so this is deliberately low priority. It changes the objective and may reduce useful ranking resolution. It is not post-hoc calibration. |
| 5 `freeze_embeddings` | Freeze parameters classified by the compiled model as `numeric_embedding`, `categorical_embedding`, or `learned_preprocessing` after epoch 4. Continue the dense network. Exact names, shapes and semantic roles must be captured before training. | Tests whether adaptation of learned input representations contributes to degradation. Fitted medians/scales that were already immutable do not count as an intervention. Freeze both optimizer updates and manual decay, and clear stale gradients. |
| 6 `head_only` | After epoch 4 retain trainability only for the final affine weight and bias, preserving their existing Adam state and LR/WD semantics. Freeze every other learned parameter; retain the specified dropout forward behavior. | Tests whether the epoch-4 representation supports useful additional head fitting. It changes the trainable subspace and its regularization, so a result is not a clean decomposition of where every generalization error originates. It overlaps route 5 conceptually but makes a much stronger restriction. |

Canonical policy dictionaries share `after_completed_epoch:4`, `horizon:16`, and `dropout_after_epoch4:0.05`. Extra keys are: `linear_lr_end_epoch:16`; `decay_factor_applications_after_epoch4:1`; `ema_half_life_epochs:1.0`; `label_smoothing_after_epoch4:0.05`; `frozen_roles:[numeric_embedding,categorical_embedding,learned_preprocessing]`; or `trainable_roles_after_epoch4:[final_affine]`. The adapter is the authority for the exact serialized dictionaries and role inventory. No unregistered threshold, multiplier, averaging window or alpha may be selected from results.

## Primary evidence refreshed and reused

Accessed October 4, 2026. The following short source summaries report methods and evaluation actually inspected, not search snippets. Exact candidate values above are our predeclared hypotheses unless explicitly identified as implementation semantics.

* [Holzmüller, Grinsztajn and Steinwart, Better by Default, arXiv 2407.04491 v3, January 15, 2025](https://arxiv.org/html/2407.04491v3): revisited architecture/training sections and Appendix B.5. Defaults were meta-tuned on 118 datasets and evaluated on 90 disjoint datasets using repeated splits. The AUC appendix compares stopping metrics and label-smoothing variants and finds label smoothing harmful for RealMLP AUROC. This argues against treating smoothing as an expected ranking improvement. Its architectures, schedules, budgets and tasks differ from ours. Numeric/categorical embeddings and feature scaling are distinct learned components, supporting explicit semantic intervention boundaries; the paper does not test our post-epoch-4 freezing policies.
* [PyTabKit issue 40](https://github.com/dholzmueller/pytabkit/issues/40): refreshed the primary issue page after the earlier source/zero-gradient reproduction. It reports repeated parameter factors in decay. Our pinned installed PyTabKit 1.7.3 source is the experiment's authority, not a mutable current main branch. The earlier ledger records author compatibility concerns and proves the installed formula, but neither proves this caused the observed score loss. Both good and bad historical recipes used it.
* [Morales-Brotons, Vogels and Hendrikx, Exponential Moving Average of Weights in Deep Learning, arXiv 2411.18704 v1, November 27, 2024 / TMLR](https://arxiv.org/html/2411.18704v1): inspected Sections 3–4 and Appendix F. Experiments use image datasets, momentum SGD, three seeds, held-out LR/epoch selection and five parallel EMA decays. Averaging can reduce update noise; normalization statistics and window choice matter. Their validation-selected EMA result is not evidence for our fixed one-epoch half-life, Adam, tabular AUC endpoint. Their frozen-feature linear evaluation uses transfer to other datasets, not our same-task head continuation. We borrow no experiment code.
* [Müller, Kornblith and Hinton, When Does Label Smoothing Help?, NeurIPS 2019](https://papers.neurips.cc/paper/8717-when-does-label-smoothing-help.pdf): inspected the target formula, representation analysis, calibration and distillation experiments. Image/translation results show that smoothing changes representation and can help some accuracy/calibration outcomes while impairing distillation. This motivates testing rather than assuming a benefit; it does not establish an AUC improvement or justify our 0.05 choice. No code is reused.
* [PyTorch 2.10 weight averaging documentation](https://docs.pytorch.org/docs/2.10/optim.html#weight-averaging-swa-and-ema): version matches the protected cloud Torch major/minor. Inspected SWA/EMA and buffer/normalization requirements. Implementation must preserve trainable-parameter identity and immutable preprocessing, and must not confuse averaged versus raw endpoint state. Averaging-function configuration is part of the saved recipe. No new dependency or library upgrade is proposed.

Existing code reuse remains PyTabKit 1.7.3 tag `v1.7.3`, commit `c126ea51187c5080b91f28d352481dbd3b2194b0`, Apache 2.0. The previously inspected [license](https://github.com/dholzmueller/pytabkit/blob/c126ea51187c5080b91f28d352481dbd3b2194b0/LICENSE.txt), local installed source hashes, optimizer scalar proof and source ledger remain in `research/deep_pass_sources.md` and `artifacts/research_pass_v1/sources/`. Installed operator behavior is pinned again in each new campaign. New policy code is local glue around this existing dependency, not an unreviewed third-party training package.

## Selection and compute decision

An initial idea was inner-only futility screening to conserve an assumed four-hour allowance. Root has since verified the actual free allowance includes a day: approximately 28.005 hours available, zero reserved. The approved plan therefore uses a full paired experiment for every route: three folds, inner and outer phases, two trajectories, 12 real fits and 192 epochs per route. Six routes total 72 real fits and 1,152 epochs before any separately bounded release refits. Root reserves six 7,200-second job caps plus bounded release/verification time within a 24-hour campaign. These are operational ceilings, not runtime or quality predictions.

The previous dropout campaign's 12 adapters totaled 3,718.322 seconds, with wrapper duration 4,331.203 seconds. These are a rough cost reference, not a guarantee: EMA adds a GPU parameter shadow, freeze policies alter backward work, and strict per-update receipts/export have overhead. Each route must pass generated smoke with its exact semantics before real fitting. Policy-specific errors cannot be repaired by weakening prefix or evaluation gates after quality is read.

Full paired runs avoid a new screening-induced selection step. They do not make the historic development rows independent. Had screening been used, combining all three inner monitors to admit a global candidate would let outer-fold labels participate through the other inner splits. Pinned incumbent OOF is also not automatically a valid inner anchor. A standalone futility gate could reject a weak but complementary blend member. Those issues are reasons to avoid claiming an unbiased nested result from a cheap screen, not arguments that screening is always unusable.

## Required evidence before quality scoring

Each new campaign needs its own immutable identity, policy, recipe, sources, data/split/anchor hashes, budget and once-only assessment protocol. Before any new metric call, validate completion of all 12 trajectories, nine logical outer predictions, six exact prefix gates and three complete-fold native-prefix checks; exact development membership and partitions; every endpoint's native model/metadata/prediction bindings; startup determinism; and actual applied optimizer/getter traces. The fixed epoch-4 network/optimizer/RNG/preprocessing/order state must match before treatment epoch 5.

The validator must allow only the named intervention after the boundary. LR changes cannot conceal WD getter or group-factor changes. Decay correction must preserve gradient LR and show an independent scalar formula. Smoothing must change the applied target getter despite its original base being zero. EMA must prove shadow ownership, update count and raw-versus-exported provenance without modifying the live trajectory. Frozen policies must bind semantic parameter inventories and prove frozen tensors unchanged, including manual shrink behavior. Native reload verification remains mandatory for the actual selected endpoint type.

Assessment remains `0.9*original_incumbent + 0.1*candidate`; the gate requires pooled and mean-fold gains at least 1e-5 against each original incumbent, control mixture and shared-prefix mixture, with every fold delta at least -2e-5. Those thresholds are operational, not significance tests. Multiple predeclared candidates and historical development reuse still permit selection bias. Report all completed routes, failures and budget stops. Do not choose a new alpha from any result or reinterpret a failed route as a successful standalone model.

Reject a parallel scan of cosine/linear LR points or dropout rates, arbitrary SWA over independently initialized fold models, unsupported best-epoch selection, and an AUC-loss replacement as the immediate continuation fix. Held-out log loss and Brier also worsened in the observed trajectory, so metric mismatch alone cannot explain the loss. A teacher-consistency objective was considered but deferred because it adds a frozen-teacher inference path and objective contract; this bounded campaign already contains six explicit mechanisms.
