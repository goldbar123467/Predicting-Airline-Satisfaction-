## The repeated-preprocessing suspicion is not supported

The methods agent explicitly retracted its preliminary suspicion for the active PBLD configuration. I agree with that retraction after reviewing both source and runtime inventory.

`nn_creator.py:157–159` does append `data_tfm` to the static pipeline inside the member loop when the single-split optimization applies. That source fragment alone cannot establish repeated nonidentity preprocessing. The actual factory determines which operations are in `data_tfm`.

In `nn_models/models.py:214–231`, the PBLD branch puts numeric preprocessing and trainable embeddings in a `ConcatParallelFactory`. `ConcatParallelFitter` inherits its split behavior from `Fitter`: `base.py:711–724` returns identity plus the fitter when it is individual; `base.py:850–875` marks the parallel fitter individual if a child is individual. Consequently the active learned transforms remain inside each member's vectorized network path. The measured inventory confirms this: three tensors shaped `[8,1,6]`, two `[8,1,4]`, and one `[8,1,9]`, all owned by the network. The static tensor inventory is empty.

There is no executed evidence here that the production recipe applies a learned centering/scaling transform eight times. Do not call this a discovered preprocessing defect, a correction, or a cause of the duration result. Other factory branches would require separate source/runtime evidence before making a claim about them.

## Limits and future integration requirements

The proof uses the production categorical schema, graph and portability helpers, plus the production transform list. The categorical adapter default is `ls_eps=0.01` with `sqrt_cos`, but the matched raw-plus-auxiliary recipe overrides it to zero: both `configs/second_pass.json` (`v2_realmlp_cat_raw_aux`) and `configs/third_pass_batch07.json` (`v3_realmlp_cat_raw_aux_e500`) explicitly set `ls_eps=0.0`. The proposed A/B/C protocol also specifies label smoothing zero. This matches the toy's `ls_eps=0` setting at line 193; there is no label-smoothing mismatch. The deliberately small hidden layers and CPU execution still mean this is not a full production-recipe replication.

The fitted statistics in this run are registered network tensors. The broader ownership traversal is useful hardening, but it does not establish behavior for every possible Python object holding an unregistered tensor. Future integration must inventory its actual active graph, including any external `common.py` feature transformer, and copy every fitted dependency used for inference. This experiment deliberately makes no external-transformer claim.

The baseline retains the same source-level audit callbacks and validation monitor as the captured arm. Therefore the intervention isolated by exact equality is the **additional** fixed fit-row probes, deep cloning, portability rewriting, tracing, saving and reloading. The test does not establish that arbitrary monitoring code is harmless. New callbacks or generator use need their own contract checks.

The native TorchScript artifact remains inference-only. Epoch-boundary optimizer/RNG replay is addressed by a separate prototype; the combined production resume path is not implemented or tested here. GPU kernels, cross-platform determinism and production resource estimates are outside this proof.

Keep the completed files immutable. The current test intentionally refuses to run when `verification.json` exists; it is a one-shot registered research check, not yet a reusable regression test with isolated temporary outputs. A future engineering test should supply a fresh namespace and preserve this original evidence.

The appropriate next step is to implement the previously proposed A/B/C adapter contract in a new isolated version, then verify its full active preprocessing, schema, eight-member inference and checkpoint behavior before any authorized real-data run. The present result reduces implementation uncertainty; it does not authorize that run or change its statistical gate.
